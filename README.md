# Task 02 — Structured Output: Validation, Retry & Self-Repair

A lightweight, zero-dependency-cost Python application that takes unstructured or flawed JSON generated by an AI model, strictly validates it against a Pydantic v2 schema, and autonomously retries or repairs invalid outputs.

The system enforces a **fail-safe guarantee**: data that fails schema validation is never returned.

---

## 1. Problem Statement

Large Language Models (LLMs) are probabilistic and often produce unstructured responses, invalid syntax, missing fields, hallucinated keys, or values outside business constraints. For downstream software systems (such as APIs, background job queues, or workflow engines) to reliably consume AI outputs, the responses must conform strictly to a contract.

Common LLM failure modes include:
- Wrapping JSON in Markdown code fences (e.g., ````json ... ````).
- Omitting required fields or inventing unrecognized fields.
- Using out-of-range numerical values or invalid enum labels (e.g., `"priority": "critical"` when only `"low"`, `"medium"`, or `"high"` are permitted).
- Producing malformed JSON (unterminated strings, unquoted keys, trailing commas).

This project implements a deterministic **validation, retry, and repair pipeline** that intercepts invalid outputs and guides them to conform to a strict schema without relying on paid APIs for development or testing.

---

## 2. Strict Schema & Validation Rules

The target schema is defined using **Pydantic v2** (`TaskResult` in `main.py`).

| Field | Type | Rules & Constraints | Description |
|---|---|---|---|
| `title` | `str` | Minimum 3, maximum 80 characters | Brief, descriptive task headline |
| `summary` | `str` | Minimum 10, maximum 300 characters | Detailed narrative of the task |
| `priority` | `Literal` | Only `"low"`, `"medium"`, or `"high"` | Urgency level of the task |
| `estimated_hours` | `float` | `0 < estimated_hours <= 200` | Task effort estimate in hours |
| `tags` | `list[str]` | 1 to 5 non-empty string items | Categorisation labels (no empty strings or whitespace) |

### Strict Enforcement Policies
- **Extra Fields Forbidden**: Configured with `extra="forbid"`. Any unexpected key (e.g. `"comments"`, `"confidence"`, `"internal_thoughts"`) causes validation to fail.
- **Malformed JSON Rejected**: Trailing commas, unbalanced brackets, or unquoted keys are caught safely.
- **Top-Level Type Check**: Enforces that the parsed JSON must be an object (`dict`). Bare primitives (`"string"`, `123`) or lists are rejected.
- **Whitespace Stripping**: String fields have whitespace trimmed before evaluation. Empty or whitespace-only tags are explicitly rejected.

## 3. Retry and Repair Workflow

The validation engine follows an iterative repair loop via `validate_with_retry(raw_output, repair_callback, max_attempts=3)`:

```
[Raw AI Output String]
          │
          ▼
┌──────────────────┐
│  Attempt Counter │ ◄────────────────────────────────┐
└─────────┬────────┘                                  │
          │                                           │
          ▼                                           │
┌──────────────────┐                                  │
│  json.loads()    ├───► [Decode Error] ──┐           │
└─────────┬────────┘                      │           │
          │ (Valid JSON Dict)             │           │
          ▼                               ▼           │
┌──────────────────┐             ┌──────────────────┐ │
│ Pydantic Validate├───► [Error] ┤ Attempts Left &  ├─┘
└─────────┬────────┘             │ Callback exists? │ (Pass prev output & error)
          │                      └────────┬─────────┘
          │ (Success)                     │
          ▼                               │ (No attempts left OR no callback)
[Return TaskResult]                       ▼
                              [Raise StructuredOutputError]
```

### Key Safety Invariants
1. **Never Silently Corrupt**: Invalid or partially valid data is never returned.
2. **Deterministic Termination**: The loop runs at most `max_attempts` times, preventing infinite loops.
3. **No Redundant Repaired Calls**: The repair callback is called at most `max_attempts - 1` times. It is **never invoked after the final allowed attempt**.
4. **Context-Aware Repair**: When invoked, the callback receives both the **most recent invalid output string** and the **specific Python exception** that was raised.

## 8. Mock Repair Callback vs. Real AI Model Integration

### The Mock Repair Callback
The included `mock_repair_callback(invalid_output: str, error: Exception) -> str` operates offline without requiring internet access or API credentials. It uses deterministic heuristics to simulate how an intelligent repair agent fixes errors:
1. Strips Markdown code blocks (` ```json ... ``` `).
2. Sanitizes fields: maps `"critical"` / `"urgent"` to allowed `"high"` priority.
3. Clamps `estimated_hours` to acceptable bounds (`0 < hours <= 200`).
4. Replaces empty or malformed tags with valid defaults.
5. Deletes forbidden extra keys.

### Replacing with a Real LLM (e.g. OpenAI / Anthropic / Gemini)
In production, you can replace `mock_repair_callback` with an LLM prompt that includes the schema and the specific error message:

```python
# Example: Production LLM Repair Callback (Pseudocode / Reference)
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

def llm_repair_callback(invalid_output: str, error: Exception) -> str:
    """Uses a real LLM to repair invalid JSON by providing the error message."""
    prompt = f"""
You are a strict JSON repair assistant.
The previous output failed validation against the TaskResult schema.

PREVIOUS OUTPUT:
{invalid_output}

VALIDATION ERROR:
{str(error)}

INSTRUCTIONS:
- Fix the error and return ONLY valid JSON matching the schema:
  - title: 3 to 80 chars
  - summary: 10 to 300 chars
  - priority: strictly 'low', 'medium', or 'high'
  - estimated_hours: number between 0 and 200
  - tags: array of 1 to 5 non-empty strings
  - Do NOT include any extra keys.
  - Do NOT wrap your answer in markdown code fences.
"""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0,
    )
    return response.choices[0].message.content
```

## 9. Design Decisions & Limitations

### Design Decisions
- **Pydantic v2 `ConfigDict`**: Leverages modern Pydantic v2 features (`model_validate`, `extra="forbid"`, `str_strip_whitespace=True`) for optimal performance and strict adherence.
- **Standard Library JSON First**: Parsing raw text with `json.loads` first decouples syntax errors (`json.JSONDecodeError`) from semantic schema errors (`pydantic.ValidationError`), allowing granular repair handling.
- **Custom `StructuredOutputError`**: Aggregates all errors encountered across retry attempts in the `errors` attribute, aiding debugging and observability.
- **Zero Paid Dependencies**: Standard library + Pydantic + pytest ensures instant reproducibility on any environment.

### Limitations
- The mock repair callback is rule-based and tuned for the demo scenarios; it is not a general-purpose semantic parser.
- Does not handle asynchronous retry pipelines (`async`/`await`), which can be added if integrating async LLM clients.
